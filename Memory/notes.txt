Memory in LLM's

A LLm at inference is just a parameterized Math Function (O/p not depend only on i/p but also on paramters)
y = fθ(x)
where:
y : o/p
x: input tokens (prompt)
θ : Billions of paramter (Therfore we say Our gpt has 2 billion parametr)

But this parameterized Math Functions are "Stateless"
Stateless: system is Stateless if o/p depend only on current i/p and not on anything that happend before.

ThereFore Fact is Concluded : LLM's do not have any intrinsic Memory.


 ✓ Context Window : is Amount of text an LLm can read and remember at one time before answering.
                    it is Maximum No of Token LLM's can processed before answering.
                    Now' day LLM have 128k token Context Window.

    LLM's use its parameter to knowledge answer, people assume but newly discovered:
 ✓ In Context Learning :In-context learning is an emergent ability that allows an LLM to use information and patterns present in the prompt itself,
                     in addition to its trained parametric knowledge, to generate an answer.

so How we can Use it to implement memory ?
    y = fθ(concation(x1, x2....xn)) // internally it work as Memory , not Stateless , but if refresh memory vanish --> this is SHORT TERM MEMORY.
    that is sending messages append in message list in prompt , by using context learning , LLM answer previous conversations.


✓ Short Term Memory
    Messages list we implement above , Also Known as Conversation Buffer
    How Implemented ? y = fθ(concation(x1, x2....xn)) : Every chat is appending with previous messages
    Drawback: 
    (i)  But if refresh page/ code reset/ start new Conversation memory of previous Conversation is vanish --> Solution : use persistance --> this is SHORT TERM MEMORY is Fragile.
    (ii) Context Window Problem : if our conversations chat/messages become too large due to lots of messages , 
         while tokenizing  previous conversations messages at new query token size also become large and 
         eventually it cross context limit of llm (llm not able to process new query in this case).
         Solution:(i) Trimming : decide/send only n messages instead of entire .problem: May miss Context ,context exist in messages which we did not send : Solution --> Summarization -> send remaining messages to another LLM to generate summary and also send summary now with that trimmed messages.
    (iii) Short Term Memory is Thread Scoped (Different Conversations limited) : memory become scoped in every diff conversation. in every new conversation it will not remember previous conversations memory.
    NOTE: In chatGpt(LLM) in every Conversation(also known thread) Short term memory is Implemented
   
     ThereFore we need new kind of memory which exist out of single conversation for long term of time.

✓ Long Term Memory
memory which exist out of single conversation for long term of time.
Three Types :
(i) Episodic Memory(Experinces) : What Happend : remeber/store What happend in past. | Episodic memory stores past interactions and experiences.
(ii) Semantic Memory(facts) : What is True : made up of facts about user , system . | stores facts, knowledge, and preferences about the user or the world.
(iii) Procedural Memory(Skills / Instructions) : How to do Things : remember How to do task.  | remembers procedures, workflows, and rules.

How it Work ?
Step 1 : Creation / update : In this During conversation we have to decide/find out,is there anything which can become part of long term memory.(exist out of Conversation)
Step 2 : Storage : Here Store Long term Memory Extract out from step 1 and add identifiers and metadata to it making it survive restart and crashes.
step 3 : RetrivaL : In new Conversation , model sochta hai , mujhe yeh answer krne kai liye kisi type ki memory ki jarurt hai ?

# Why Persistanc checkpointers are not Long Term Memory ?
Long-term memory is meant to store useful knowledge for future conversations.

Example:
User prefers C++ for DSA questions.
User is building a RAG project with LangGraph.
User uses Groq API.
These facts should be available weeks later in a completely new conversation.

A checkpointer does not decide what is important knowledge. It simply records the entire runtime state.

Rule to Remember
Checkpointer = "What was happening in this conversation?"
Long-Term Memory = "What should I remember about the user or past experiences for the future?

Why Confuse happen ?
if your graph crashes and you restart it, the checkpointer can restore the graph state from disk. That feels like “memory”, but its purpose is different.

When use which ?

** Persistence / Checkpointing
Crash recovery
Streaming and interrupts
Human-in-the-loop approval
Time travel / debugging
Resume execution

** Long-Term Memory
User personalization
Remembering preferences
Remembering past projects
Cross-session knowledge
Agent learning/history.
